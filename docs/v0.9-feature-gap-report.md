## 2. What the HTML prototype does

### 2.1 Layout and navigation
- Header: app name/version, **Export well** (JSON), **Import** (JSON → new independent well).
- Workspace bar: **Well Design · Well Calculations · CT Calculations** (three workspaces sharing geometry and catalogue).
- Well bar: **active well picker**, **+ New well**, **Duplicate**; badge shows example/user/imported source.
- Left card: interactive well cutaway (SVG). Right card: editor with tabs
  **Well info · Formations · Holes · Strings · Completion · Trajectory · Volumes · Cementing · Wellhead · QA**.
- Footer disclaimer: geometric only, not for field decisions.

### 2.2 Editors (Well Design)
| Tab | Controls |

### 2.4 Calculations in the HTML
| # | Calculation | HTML formula |
|---|---|---|
| H1 | Capacity | π/4 · ID² (in → m) |
| H2 | Internal / annular volume | Σ over catalogue intervals of π/4·ID² · L, or π/4·(host ID² − pipe OD²) · L |
| H3 | Cement lead/tail | Σ π/4·(host² − OD²)·L·(1 + excess); host = innermost outer casing ID or hole bit size; split at tail top |
| H4 | Shoe track / displacement | internal volume shoe↔float collar; top↔float collar |
| H5 | CT active path, tubing annulus, CT-occupied, CT return annulus | piecewise bore capacities from wellhead MD (RKB − wellhead height) |
| H6 | CT internal volume | π/4·CT ID² · deployed length (+ surface line) |
| H7 | Pump time / velocity | volume ÷ rate; rate ÷ local capacity (m/min) |
| H8 | Hydrostatic (CT) | ρ·g·TVD; overbalance = hydrostatic − formation; density to meet target; EMW = SG × 8.3454 ppg |
| H9 | Perforation loading | gal/ft × perforated length (ft) ÷ 42 |
| H10 | Cement plug / squeeze | bore capacity × column; + squeeze volume + spacers + contingency |
| H11 | Job timeline | Σ fixed minutes or bbl ÷ bpm |

## 3. What the Android app already does better (keep)
- True trajectory from surveys (minimum curvature) and correct MD/TVD/GL/RKB/MSL handling.
- Data-driven surface equipment: wellhead in cellar on a landing base, drilling BOP, Christmas tree,
  CT stack and injector, all at one true scale (owner-approved reference stack-up).
- Completion states (as-designed / as-built / current), completion components with OD/min ID,
  perforation status, cement status, shoe type, float collar.
- Calculations v1 with 4-way verification (independent Python, oilfield rules, v0.9 cross-check,
  invariants) and outcome audits; CT passability, placement, full-path smallest restriction.
- Room persistence, autosave, JSON codec, units (oilfield, metric, field-metric).

## 5. Integration plan (existing code preserved)
1. **Stage 1 (this PR):** tubular catalogue with provenance and consistency tests; blank-well
   factory; structural edits (add/remove strings with type and catalogue size, holes, formations,
   tubing); New well / Duplicate / Delete on Home; editors in Well Design. Demo wells stay as
   optional examples. No existing calculator or drawing code is replaced.
   *Stage 1 status:* done in `feature/well-editor-catalog` — see §5.1.
2. **Stage 2:** completion equipment editor; tapered strings; object-based volume calculator;
   cement job editor with lead/tail; well info fields; JSON import/export; QA screen.
3. **Stage 3:** CT workbench panes from the owner's workbook; wellhead photo; conductor stick-up.
4. **Stage 4:** extended catalogue from the owner's approved sheets (SLB / Halliburton) once the
   source and licence are confirmed.

### 5.1 Stage 1 — what the user can now do
- **Home:** `+ New well` (name, onshore/offshore, RKB above GL, GL elevation above MSL, in the
  display units) creates an empty user well and opens Well Design; `Duplicate` and `Delete`
  (with confirmation) act on the active project. If every project is deleted, the labelled
  synthetic demos are seeded again on the next launch (existing seeding rule, unchanged).
- **Formations:** add / remove, name, lithology, top TVD below GL; kept in depth order
  whatever datum a top was entered from.
- **Hole sections:** add (next smaller bit, 500 m deeper) / remove, bit size from the
  pick-list, bottom MD; the next section's top follows a changed bottom.
- **Casing strings & liners:** add / remove; **type** (conductor, surface, intermediate,
  production, intermediate / production liner, tie-back); name; **OD → nominal weight →
  grade → connection** from the catalogue with wall, ID, drift, capacity and the source shown;
  top / liner top, shoe, cement add / remove / TOC, float collar add / remove.
- **Production tubing** (completion states only): install / remove, catalogue size, EOT.
- `+ Add casing / liner` proposes starting values only: the usual next type; the largest
  catalogue OD that passes the drift of the string outside it and is smaller than the bit of
  the next hole section; lightest weight; shoe at the deepest hole section it fits in; a liner
  hangs 150 m above the previous shoe. The user then edits every value.
- The sketch, key depths, geometry checks and all calculations update from the edited well at
  once (same pure edit functions and validator as before).

### 5.2 Stage 2a — done after the cross-check
- **Volume by string** (Well Calculations): inside a chosen pipe, or the annulus between it and a
  chosen outer casing / the open hole / automatic, over an MD interval; segment table.
- **Lead / tail** cement split (tail slurry top per string, editable in Well Design) and a
  **cased-hole excess** input next to the open-hole excess.
- v0.9 QA rules added to the geometry validator (see `docs/crosscheck/v09-scenario.md`).
- Cross-check: the v0.9 functions and Android agree to 1e-9 m³ on a synthetic well built
  through the editor (volumes, annuli, cement lead/tail, shoe track, displacement, CT annulus).

## 6. Calculations requiring validation (flagged)
Status in the app: every formula is **"Implemented, pending validation"** until the owner signs off
with worked examples. Items below need explicit validation before field use.

| Calculation | Where | Why it needs validation |
|---|---|---|
| Capacity / internal / annular volumes | Android v1, HTML H1–H2 | Nominal body ID only; tool joints, couplings, washout excluded |
| Cement slurry volume, excess, rathole | Android v1, HTML H3 | Excess policy is user-defined; caliper/washout, stage tools, liner top not modelled |
| Lead/tail split, slurry densities, spacer | HTML H3 (stage 2) | Not yet in Android; sacks/yield/mix water not defined |
| Shoe track and displacement | Android v1, HTML H4 | Excludes cement head, plugs, surface lines |
| Hydrostatic pressure, EMW | Android v1, HTML H8 | Static single-density columns only; HTML uses SG × 8.3454 ppg — check against the owner's convention |
| CT volumes, pump times, velocities | Android v1, HTML H5–H7 | Incompressible, no friction; HTML velocities in m/min |
| CT smallest restriction | Android | BHA-below-stripper rule is provisional; no clearance criterion set |
| Perforation loading, plug/squeeze, timeline | HTML H9–H11 (stage 3) | Workbook logic; HTML notes workbook QA issues: `Completion!L15` unit label, `N45/N46` wrong rate cells, `L78/L79` swapped capacities, `I2/H2/J2` inconsistent OD/ID/weight |
| Catalogue dimensions | HTML rows | Public references, not OEM certificates; grade/connection ratings unverified |
| Casing-in-casing fit and hole clearance | Android `WellStructureDefaults`, validator | Only body OD < drift (else ID) and OD < bit are checked; **coupling OD, annular clearance for cementing, and centraliser stand-off are not checked** |
| 150 m liner lap, 200 m default TOC, 25 m float collar, tail over the lower third | Android editor starting values | Placeholders for editing, not design rules; the owner should set company defaults |
| Volume by string | Android `ObjectVolumeCalculator` 1.0.0 | Agrees with v0.9 `volume()`; one size per string (tapered strings not modelled) |
| Lead / tail split | Android `CementVolumeCalculator` 1.1.0 | Agrees with v0.9 `cementVolume()`; slurry yield, sacks, mix water, spacer and densities not included |
| Conventions that differ from v0.9 | See `docs/crosscheck/v09-scenario.md` table | Displacement without float collar, CT time-to-nozzle basis, CT volume start depth, EMW datum |
